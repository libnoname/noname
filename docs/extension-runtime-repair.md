# 扩展启动报错与列表消失修复（2026-09-10）

## 已定位的原因

- `清瑶葭绮/members/假装无敌/extension.js` 的旧 APK 启动入口引用了不存在的 `_0x580f`，precontent 中断，随后 content 访问尚未初始化的 `lib.qyUtils.debounce`。这不是单纯缺少 debounce。
- 合并器原先没有成员级错误隔离；一个成员失败会导致同包后续成员无法登记。
- 旧版“禁用扩展并重新打开”会将全部扩展开关设为 false。文件仍在，但停用扩展不会出现在武将包页。
- 玩点论杀没有返回/等待模块加载 Promise，可能在武将注册阶段之后才完成导入。

## 修复方式

- 清瑶武将和卡牌数据改为可等待的模块工厂，合并到清瑶葭绮，不执行旧 APK 的 UI、开发模式、缩放及引擎替换补丁。旧入口保留为不调用的参考函数，图片、音频和技能定义未删除。
- 初始化该包独有的 `characterLiuwei`，避免核心注册器遇到不存在的目标字段后中断。
- 合并器和手杀 APK 合并器逐成员隔离导入、precontent、content 错误；初始化失败不再调用该成员的 content。错误仍会报告，不以忽略报错掩盖失败。
- 成员配置补齐 `enable: true`；玩点论杀等待两个模块完成导入。
- 旧 `characterPrefix` 字段转换到当前引擎的 `translate.<武将ID>_prefix`，防止手杀“新武将”等成员再次中断注册。已有翻译优先保留。
- 神刘备“结营”改用自身已有的两个子技能，补上符合该扩展原技能描述的全局手牌上限效果；不修改核心同名技能。
- 银灰 `xxy_yinhui` 的 `xxy_guima`、`xxy_shenpan` 在现有资源中无实现：保留资料和原技能列表，仅限制该武将进入对局，待补齐后自动解除限制。不用空技能或其他技能冒充。
- 威马超 `wei_machao` 的 `weijizhan` 在源扩展中被注释，同样保留资料并限制进入对局；不影响其他手杀武将。

## 如果已点击过“禁用扩展”

刷新游戏后，全部停用时会显示“扩展当前全部停用（资源仍在）”。检查面板列出的包，点击“恢复上述扩展并重新打开”。

- 新版紧急禁用会先记录已开启包的名称，再等待关闭设置写入后重启，可准确恢复原开关。
- 旧版没有这份记录，不能推断哪些开关曾是手动关闭。恢复面板会明确列出默认兼容清单，由用户选择是否恢复；未列出的包仍停用。
- 不清空 localStorage、不删除 IndexedDB、不重置战绩、主程序或其他设置。
- 扩展页与武将页均按 PXLNGU 统一收纳成员。武将页初次构建、重新构建和后加载成员共用同一归属表，避免重新散列。关闭的扩展仍在扩展管理页可见，武将页保留 PXLNGU 管理入口。
- 手杀 APK 成员还有各自的开关；如果它们以前被关闭，开启“手杀武将”总开关不会擅自重置子开关。请在该扩展内开启需要的“APK 武将 · …”后重启。

## 验证范围

- 实际浏览器身份模式：清瑶葭绮 74 个、风云浮生明辉月 36 个、觉醒突破 15 个武将条目均注册；原名将杀仍显示。
- 手杀所有兼容子包启用时，69 个清单 ID 中 50 个在本包登记、19 个沿用主程序已有定义，无需重复新增。势魏延仍保持原有待兼容状态。
- 修复后的身份模式启动未再产生新的扩展启动异常。检查剩余缺失技能属于银灰与威马超，均已限制选用。
- 自动测试覆盖真实清瑶包生命周期、失败成员隔离、卡牌属性复制和紧急恢复持久化顺序。
- 这些是启动、注册与配置恢复验证，不代表每个旧扩展的全部技能、模式组合均已逐局测试。未兼容包不会因本次修复被自动全部开启。
