# 首次加载、动态原画与名将杀技能修复

本次按要求仅进行源码排查与修改；没有启动游戏、运行测试、构建或打包。以下为代码层面的处理，不是实测性能结论。

## 加载

- Vite 预先发现常用依赖并预热入口模块，减少第一次打开页面时的转译和依赖优化等待。Vite 配置变动需要开发服务重新加载后生效。
- 启动只等待 DOM 可用，不再等待 window.load（图片、字体、其他装饰资源）。Vite 开发环境直接安装已配置代理的文件服务接口，避免慢探测令 game.getFileList 等方法缺失；非开发浏览器才做 3 秒有界探测。
- 在线房间组件按需导入，大厅组件移出核心静态依赖图。入口 HTML 在模块初始化之前就显示载入提示；大厅或对局就绪后移除。提示本身不代表资源加载已经加速。
- 公共 setBackgroundImage 恢复同步设置背景和原有 CSS 回退层。选将界面、卡牌副本会立即读取或复制背景样式，不能等异步解码后才写入；预取只填充缓存，不再接管显示。
- 只预取当前牌堆的卡面，最多两个预取请求并发，不预加载全武将库。图片请求去重，历史缓存限制为 256 项（仅持有 Promise），单个图片失败/超时不会卡住预取队列。
- 补齐当前字体、点数和花色的提前加载；旧界面扩展的三种文字字体使用 font-display: swap，避免文字先隐形再出现。

## 黛玉动态原画

- 移除原有 3 秒强制等待，以及原画等待空闲回调的额外延迟。
- 出现黛玉选将图片时，准备一段当前可能使用的原画视频和首帧图；确认武将后复用视频元素。不同时预加载两套背景和原画。
- 预备视频最多保留 30 秒，切后台、关闭动态或销毁时释放；开启省流模式时不提前请求视频。
- 武将初始化完成立即通知外观模块，不再等一秒定时轮询。视频首帧出现后的淡入缩短至 200ms。
- 原画优先于尚未就绪的背景视频；继续保留首帧占位、后台暂停、播放失败/持续掉帧回退和解码数量限制。

## 名将杀

已修正以下技能中的变量、回调参数或返回值使用问题：

- 击牛飨士：AI 增强判断使用技能拥有者 player。
- 谦冲节下：阶段开始时读取当前玩家的技能。
- 潜谋远计（现版、旧版）：目标选择 AI 的参数改为 target。
- 负鼎见胁：检查实际出牌者造成的伤害历史。
- 土高代汉：从玉玺实际持有者取得牌，并将交换牌交给该持有者。
- 应势布阵：直接解构 forResult() 的 bool/moved。
- 徙木立信：声明 event.target；第二次选人使用 result2，避免读到后方局部 result 的暂时性死区。
- NPC 风影：标记使用当前回调的 player2。
- 兰艾同焚：销毁筛选使用已定义的 filter。
- 华亭鹤唳：创建卡牌使用 event.cost_data。
- 神亭酣战：用牌事件 next 在循环体内声明，只有确实用牌后才检查其导致的濒死。
- 旧运筹帷幄：筛选 card.name，避免误用逗号和未定义 name。
- NPC 盘查：查看实际选定的 target 手牌。
- 重农励战：使用 prompt2；从触发事件取得实际受影响角色。

旧式分步 content/onEquip/onLose 等由引擎注入的变量不作为未声明变量批量替换。

## 文件服务与名将杀启动补充修复

- 纠正上一轮 800ms 探测超时导致开发环境文件接口未安装的回归。开发环境不再用一次探测判断接口是否存在，实际文件操作仍报告服务错误。
- 新增扩展的可选目录扫描失败时，继续加载已登记扩展，不因文件服务暂不可用中断整个启动流程。
- 名将杀使用 main/runtime.js 中的明确模块清单，移除启动时递归扫描目录和 eval 拼接目标的做法。即使静态浏览器没有文件服务，也能通过普通模块请求安装基础规则。
- precontent 改为异步：等待基础方法、过滤器、技能、钩子和翻译全部合并后再导入武将、卡牌和模式；所有导入都由核心启动流程等待，避免遗漏 Promise 与加载竞争。
- 保留扩展恢复入口；旧版本紧急停用留下的有效快照在下次启动时恢复，具体修正见下节。
- 本轮仍未运行游戏验证、测试、构建或打包。

## 原画、界面及刷新丢包回归修复

- 撤掉公共图片接口的异步显示，修复复制选将节点时读到空背景的问题；图片预取失败不缓存为永久失败，动态视频的首帧切换逻辑保留。
- 当前界面的快捷菜单入口复用已有“对局操作”对话框，避免打开旧版四个大圆按钮。经典界面保留原快捷菜单；未重新设计菜单或修改布局、配色、字号。
- 浏览器 game.exit 复用已有返回主界面流程，清理当前对局入口后重载，不再尝试 window.close 后主动抛异常。桌面退出实现不变。
- 红楼幻境加入固定扩展清单，首次登记时恢复启用，以修复此前目录扫描和恢复清单遗漏导致的命包缺失；登记完成后继续尊重用户开关。
- 已登记且启用的扩展如果在加载列表中缺失，会补回；手动导入的包也记录登记历史。恢复快照不再仅限内置名单，允许恢复合法名称的自定义扩展。
- 旧版“全部关闭”遗留有效快照时，先恢复原开关再加载；无快照不猜测原开关，仍提供现有恢复入口。新的紧急跳过只影响本标签页下一次启动，不持久关闭扩展，普通刷新会恢复按原开关加载。
- 数据库写入等待 transaction.oncomplete 后才释放重载等待；异步保存接口传递实际保存失败，避免恢复按钮挂起或在未提交时重载。
- 配置导入失败继续读取已有数据库，保留导入文件；部分导入不会把未涉及的扩展/界面设置替换为空。导入写入完成后才移除文件。
- 开发服务固定 8081 端口，端口占用时明确失败，不静默改到新端口产生另一份空存档。localhost 与 127.0.0.1 的存档依旧遵循浏览器来源隔离；继续使用原先的 http://127.0.0.1:8081，不做跨来源覆盖或清空。
- 以上仅完成代码修改，按要求未进行浏览器验证、测试或构建，尚无实测性能与恢复结果。
