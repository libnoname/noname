# 清瑶版 APK 扩展资源增量合并

本次从 `无名杀清瑶版（v1.12.7.0711_β）.APK` 内的 `assets/noname-decade.zip` 提取扩展资源，并按“只新增、不覆盖”原则合入 `apps/core/extension/`。

## 合并结果

- 新增 46 个工程中原本不存在的扩展目录，共 9,772 个文件，约 1.20 GiB。
- `仿官复刻` 增加 119 个 APK 独有文件；已有 479 个同路径文件未覆盖。
- `手杀武将` 增加 182 个 APK 独有文件；已有 51 个同路径文件未覆盖。
- `boss`、`cardpile`、`coin` 没有 APK 独有文件，因此没有修改其内容。
- `神马超` 仅提供已由 `柊舞缇娜` 登记的 `mb_shen_machao`，作为明确的功能重复未合入。

同名目录合并后的复核结果：`仿官复刻` 保留 9 个工程差异文件，`手杀武将` 保留 2 个工程差异文件，`boss`、`cardpile`、`coin` 各保留 1 个工程差异入口；APK 资源缺失数均为 0。

## 兼容处理

- 44 个旧式 `game.import("extension", ...)` 入口已转换为当前 ESM 扩展入口。
- 混淆入口扩展 `无名助手` 仅补充当前模块所需导入，保留原侧效应注册方式。
- `AIoptimize` 是 `play` 类型，已作为内置玩法扩展登记。
- `假装无敌` 原入口中的 `delete player` 在旧版宽松脚本中是无效操作，但在 ESM 严格模式中属于非法语法，已替换为等价的无操作表达式 `void player`。

## 启用与安全边界

45 个普通扩展在 `organized-extensions.json` 中标记为 `defaultEnabled: false`；`AIoptimize` 的默认玩法列表也保持关闭。因此新资源进入工程和构建产物后不会在首次启动时自动改变现有玩法。

本次完成了 ZIP 路径、长度与 CRC 校验、安装后文件哈希校验、46 个入口的现代 JavaScript 语法检查、扩展登记测试和完整工程构建。复杂扩展仍可能依赖清瑶版特有 API 或其他扩展，启用前应逐个进行实机测试。
