# 扩展整理复查记录（2026-09-09）

本记录对应复查时本机 `扩展包/武将扩展` 的内容，是一次核验快照。后续增删扩展请以最新 `扩展包/整理结果/整理报告.md` 为准。

## 结论

313 个源文件均已核对并有记录，没有发现未登记的源文件。初版确有内嵌 ZIP 漏扫和只读代码误判，本次已修复并重新整理。

这不表示所有扩展已成功转换或通过实际对局测试。当前输出 49 个扩展，共 474 个不重复的武将 ID；其余处理项有明确的跳过或重复记录。

## 修复的发现

初版遇到扩展入口后不再检查同包中的内嵌 ZIP，涉及以下三个源文件：

- `(武将)阵面士兵扩展包，武将52+配音版.zip`
- `（武将+模式）剧情三英.zip`
- `经典丨天下无双.zip`

现在每个直接入口与内嵌 ZIP 都会单独登记；目录相互嵌套而不能拆分时，也不会阻止其他入口和内嵌 ZIP 的检查。

代码检查原来把所有前缀运算都当作修改，因此 `!lib.character[id]`、`!lib.skill[id]` 这样的只读判断会被误报。现在仅赋值、删除、自增和自减属于写操作；其他保守检查仍有明确的“不支持自动分析”说明。

同时补强了同一源包内部的排序，使用真实路径段决定顺序，避免显示文字“根目录”影响优先级；外层许可证和 README 按原始字节保留，避免非 UTF-8 文档被误拒绝或改变内容。

增加了相应回归测试，当前 16 项测试通过，TypeScript 类型检查、ESLint 和 Git 差异检查通过。

## 为什么武将数量由 490 变为 474

补扫发现了较早来源中的 52 人“士兵扩展包”。按“第一个出现的保留”及内部扩展名不能冲突的规则，它取代了后来同名的 77 人版本；另外接纳“长衫”1 人、“阳光包”8 人。

```text
490 − 77 + 52 + 1 + 8 = 474
```

因此数量下降是来源选择变化，不是生成 ZIP 时丢失资源。后来的同名版本仍在原始输入中，报告注明内部名称冲突。旧生成结果由整理器更新，可随时从原始包重建。
