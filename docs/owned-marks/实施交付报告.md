- `apps/core/noname/library/element/ownedMarkStore.js:65`：独立纯数据账本，版本 1。每个 bearer/name 保存匿名旧数量及来源实例列表。

- `apps/core/noname/library/index.js`：重连重建 Player 后导入状态；`content.ts:12544` 在死亡结算完成且仍死亡时执行策略。
- `player.js` 的 reinit、uninit、removeSkill 和 Game 永久移除入口分别接入精确生命周期清理。

记录表达 `{id,revision,name,bearer,creator,owner,beneficiary,count,params,sourceSkill,lifecycle}`，身份是明确分配的字符串，不存 Player 引用。稳定实例身份独立于 playerid、武将名和座位；网络通过明确 playerid 绑定当前实体，录像／显式存档通过其记录的位置映射，已永久离场的 detached 身份不绑定同座位替代者。

关键不变量：`storage[name] = anonymous + Σ count`。数量是安全整数；参数为有限、无环 JSON；同来源不同参数保留独立实例。私有草稿完成校验后一次同步提交 revision，之后才投影 UI 和发送状态。完整转移保留实例 ID，部分转移拆新 ID；显式合并仅允许全部元数据兼容的实例。过时 revision／已消费 ID 无法再次消费。重入事务仅发布最终状态，不重复数量事件。

## 二、API 与兼容性

已提供 addOwnedMark、getOwnedMarks、countOwnedMark、hasOwnedMark、getMarkOwners、removeOwnedMark、consumeOwnedMark、transferOwnedMark、updateOwnedMark、mergeOwnedMarks、clearOwnedMarks，以及 Game 身份、导出／导入、保存／加载与生命周期接口。签名、返回值、消费示例和参数规则见 [API说明.md](API说明.md)。

旧 addMark/removeMark/setMark/countMark/hasMark、数组 markAuto、自身资源、共享标记不自动认主。不替换 `storage[skill]` 为 owner 对象。未启用账本的键保持原实现；已启用键的旧 add 创建匿名份额，旧 remove/set/clear 仍是聚合操作，先扣匿名再按记录顺序扣有来源份额。旧调用不凭空推断来源；新私有收益必须选择 owner／实例消费。

直接写入数值 storage 后调用 syncStorage 会协调账本；未经同步的任意直接写入无法被普通对象拦截。数组标记不能覆盖已启用的数值账本。旧录像或存档无来源信息时保留匿名兼容数据，不能据当前事件猜原 owner。`syncStorage` 没有被当作网络同步的替代品。

## 三、生命周期、触发与恢复

默认 ownerDeath=retain、bearerDeath=remove、skillRemoval=remove、reset=remove；具体技能可覆盖。永久移除清理相关实例；游戏重新准备重置会话。暂离、断线、暂时禁用技能不自动销毁；技能另查当前有效资格。复活不会重新生成已按规则销毁的记录。

同名技能依然按各 Player 注册；不重写 global 去重或 GameEvent 队列。现有 arrangeTrigger 的 filter 重检和新同步 consume 共同避免候选排队后重复领取。普通营先消费再 give；国战先把自己的营移回自己再 give；另一 owner 的份额不受这一步影响。相同目标手牌收益按实际结算顺序移动，后者不会复制前者已经拿走的牌。

网络使用带会话／单调 revision 的完整 JSON 字符串快照，避开旧通用编码器的递归深度及保留字符串解释。重复／旧包不回滚状态；非法身份映射先整体拒绝。录像单独记录 ownedMarks 数据，恢复安静投影；不会重新发奖励或广播。onOwnedMarkChange 重建夺锐禁用理由、附加技能提供者和焰狱辅助技能；恢复幂等。Live 删除仍执行真实 onunmark 清理。

存档接口明确保存这份账本，需模式在普通中局状态重建后调用；不会把棋战的战役进度保存冒充完整战斗存档。协议、旧数据与保存边界详见 [recovery.md](recovery.md)。

## 四、技能规则与迁移范围

- 普通／国战劫营：每来源独立生成一营；同目标允许多来源；转移不改 owner。增益按 bearer 身上当前有效 owner 去重，每来源 +1，既不按数量也不按全场无关持有者放大。普通回收清自己的营，国战回收营归自己；自己的营不向自己收取手牌。两版描述已更新。这是用户批准的新认主规则，未把旧共享文本伪称为唯一原规则。
- 节谏：每来源／目标一条记录，参数保存该来源最近赋予时的体力阈值；同来源重复更新自己的阈值。保护资格可以共享，回合末奖励只消费自己的关系，匿名旧数量不奖励任意人。
- 焰狱：每次施加保留独立花色实例；转化取全部关系花色并集，奖励仅看行动者自己的来源与花色，单次用牌不因多笔相同实例重复奖励。永久转化按原文保留死亡／原技能移除后的关系，角色重置清理；旧数组仅作匿名转化兼容。
- 夺锐：稳定关系键保存 params.skills；实例 ID 作为禁用 reason 和 AdditionalSkill provider。删除一份只恢复该份禁用／借技；恢复会重建派生状态。
- 易宠：新发动明确清除全场本技能族动态雀标记，包括死亡／暂离者；不将全场清理缩成当前 owner，也不删除主技能或无关辅助技能。

保留共享：梦魇、傀、平定、猎、信众、毒等；保留自身资源：暴怒、忍戒、军略等。已有来源机制的大雾／狂风／随征等未机械重写。需独立语义审查：dcshengdu/yijiao、眩惑变体、鬻爵变体、埋祸、秘诏危迫、佐幸、私掠等。完整分类和候选局限见 migration-catalog.md 与扫描 JSON，不将搜索命中数当缺陷数。
